# solofact 设计规格与实验记录（SPEC）

本文回答「**为什么是这样**」和「**什么还没定**」。用法看 [README](../README.md)，演示库看 [vault-5w2h/README.md](../vault-5w2h/README.md)，发布流程看 [RELEASE.md](../RELEASE.md)——那三份是「是什么、怎么用、怎么发」，本文是「当初为什么这么定、哪些还是实验变量」。

> **重建说明**：本文档于 2026-10-15 由历史设计讨论重建，全部条目经代码与契约实证核对（核对来源随文标注：`contract/`、`core/*.js`、`cli/`、`plugin/`、测试运行结果）。章节编号沿用原 spec（§5.2 = 形态 A/B 实验设计、§8 = 开放项），保持历史引用有效。

## 1. 问题与立论

solofact 源自一个 CRM 实验（solocrm）的死因复盘：**工具不差，但没人坚持记**。

由此立下本项目的基本假设：

> 录入摩擦是「坚持记」的第一杀手。把摩擦压到最低（必填只三个字段），同时让每次记录**当场产出可看的视图**（记录有回报），坚持记的发生率会提高。

solofact 是这个假设的验证实验。因此本项目的验收标准从来不是「功能齐全」，而是「**有没有人在持续地记**」。当前状态：工程侧已可分发，但**真实使用数据一天都还没开始积累**（见 §8-B）——实验尚未真正开跑。

## 2. 架构护栏（不可动）

这些不是偏好，是防止「规则分叉」的结构性约束，改动需先改本文再改码：

- **一内核两壳**：`core/` 是纯函数核（不碰文件系统、不取当前时间），CLI 与 Obsidian 插件都只是调用者。
- **规则只有一份**：契约 `contract/enums-5w2h.json` + 校验 `core/fact.js#validate`，两个壳不许自带校验。
- **落盘顺序锁死**：真源（`<主题>/_真源/facts.ndjson`）先于 Markdown；致命错误一个字节都不写（`core/record.js#record`）。分叉的后果是「Markdown 存在但真源没有这一行」——正是本项目要消灭的静默错误。
- **插件只写不看**：不渲染表格、不做仪表盘；查看全部交给宿主 Obsidian 的 Bases。
- **测试锁架构**：`tests/` 35 条（内核 + CLI 子进程退出码契约 + 插件静态守卫「壳不许越界」）。

## 3. 数据形态：主题 = 目录

**主题不是事实里的一个字段，而是一堆事实的上级目录。**（2026-10-12 定论）

```
<库>/
├── <主题>/                   ← 一个主题 = 一个自包含目录
│   ├── _真源/facts.ndjson    append-only 真源（每条一行 JSON）
│   ├── 事实/f-*.md           读模型：一条事实一个文件
│   ├── <主题>.base           Bases 视图（八个看板）
│   └── 时间线.md / .html     该主题的可视化时间线
├── _体检.md                  ← 库根：跨主题汇总诊断（全库共享一份）
└── .obsidian/types.json      ← 库根：属性类型注册表（全库共享一份）
```

论据：

1. **没有 `type` 这一级**。主题从字段升格为目录后，同主题内 `howmuch` 天然同一量纲（记账都是元、体重都是 kg），类型模板和单位/口径校验失去存在理由——`validateAmount` 因此只校验「是不是数字」（`core/fact.js`）。
2. **删一个主题 = 删一个目录**，干脆；没有主题注册表要维护。
3. **无跨主题总览**（2026-10-12 决定：主题完全独立）。跨主题的汇总只有库根 `_体检.md` 一份诊断。
4. **真源是 append-only 的 ndjson**，Markdown / `.base` / 时间线都是**可随时重建的读模型**——数据不会因为改视图而损坏。完整论证链（2026-10-15 补全）：**工程上**，追加是唯一「写坏了也不波及已有行」的操作——重写/压缩有崩溃窗口期，半途失败会损坏既有数据，这是 §2「致命错误一个字节都不写」能成立的前提；**领域上**，「事实」= 已经发生的事，发生的事不可原地修改——一条能被静默篡改的记录不可信，而「不敢信的库」比「录入 friction 高的库」死得更彻底（solocrm 教训的镜像面：没人坚持记的库是懒得记，没人敢信的库是烂掉了）。所以记错的补救从来不是改旧行，而是加新行 + 删旧行（复制+删除闭环，§7），历史的审计外包给 git。**推翻条件**：若 B 阶段数据显示用户因「不能改内容」而放弃记录，复盘时重开此议题（备选：版本链 / tombstone+编辑 UI）；在此之前它是 §2 级护栏，不是实验变量。

## 4. 记录结构：5W2H

一条事实 = 5W2H 八个字段（`contract/enums-5w2h.json` v2）：

| 字段 | 必填 | 类型（`core/vault.js#TYPES_5W2H`） | 说明 |
|---|---|---|---|
| `who` 谁 | ✅ | text | 自由文本；插件侧是**输选框**（历史候选可复用，也可手填新建）。**缺省规则＝「唯一才缺省」**（2026-10-22 用户拍板）：本主题历史 who 只有一个取值时预填它（单人库零摩擦且不可能填错），出现 2 个以上取值就**不预填**——复用由候选下拉承担 |
| `when` 何时 | ✅ | date | 发生日；日期必须原样往返，脏日期不静默成功（`parseDate`） |
| `time` 时刻 | — | text | HH:mm；分钟精度的权威落点是 id；内核自动打戳 |
| `what` 啥 | ✅ | text | 正文（`makeFact` 把 `what` 规范为 `content`） |
| `where` 在哪 | — | text | |
| `why` 为何 | — | text | |
| `how` 方式 | — | text | |
| `howmuch` 多少 | — | number | **有符号数**，见下 |
| `recorded` 记录日 | — | date | 录入日，与 `when` 的前后关系有校验 |

设计论据：

- **必填只有 who / when / what**——直接对应 §1 的立论：录入摩擦压到最低，其余可选可空，不补不报错。
- **枚举从数据抽、按主题作用域**：契约里 `enums: {}` 是空的（设计，不是漏配）。候选在运行时从**该主题**已记过的事实抽取（插件 `historyOf`），词汇内聚不跨主题混。这是「自由录入」与「聚合复用」的统一机制。
- **`howmuch` 是有符号数**（2026-10-13 定调）：核心只校验「是不是数字」，正负零全放行。符号是**主题级约定**（资金主题 负=出、正=进），核心不可能知道每个主题的语义——全局判正负就是被删掉的 type 校验的还魂。
- **日期不加引号落盘**：宿主属性面板会把加引号的日期判成文本，Bases 就无法排序/分组/算区间（`dumpValue`）。
- **没有 `tags` 字段**（2026-10-22 移除，§5.2 第一例数据驱动的形态变更）：0.4.0 时代为「契约-表单对称」补的字段，实测全库 **0% 填充**（含种子用户真实记录）——没有任何视图消费它（`.base` 只按目录过滤），却把 tags 输选框的候选污染成唯一无意义值。字段要么有人用，要么不存在。

## 5. 形态演进与 A/B 实验记录

### 5.1 已废弃的形态（及废弃理由）

| 形态 | 内容 | 废弃理由 |
|---|---|---|
| v01 三层实体 | 客户/联系人/事实三层 + `shape` 开关 | 2026-10-12：记录结构是实验变量，可大幅重做；三层实体是默认假设不是需求 |
| type 级 | 度量算法模板 + 单位校验 + `fact-types.json` + `typeTemplate.js` | 主题=目录后，同主题 howmuch 天然同义，整套失去存在理由，已全部清除 |
| `tags` 字段 | 契约字段 + 表单行 + CLI `--tags` | 2026-10-22：§5.2 复盘第一例——填充画像实测全库 0%，无视图消费，纯摆设还污染候选下拉。已从契约/内核/壳/文档全链路移除；旧数据里的 tags 读得出但报 `W_UNKNOWN_FIELD` 告警 |

### 5.2 A/B 实验方法论（原 spec §5.2）

- **记录结构/形态是实验变量，不是要固化的产品。** cli / skill / Obsidian 插件都是验证产品形态的手段，不是目的。
- 当前进行的实验：**5W2H 最低必填（who/when/what）与记录自由度的平衡点**——必填再少，事实不成形；再多，坚持率下降。分界在哪里，由真实使用数据回答，不由设计者拍脑袋。
- **「插件降低录入摩擦」没有人手秒数对照组**（2026-10-12 澄清）：CLI 是 agent 录入通道（配 `skill/SKILL.md`），不是人手界面。插件面对的是 Obsidian 里的人，实验对象是人的坚持行为。
- 实验方法：真库自用/试用 → 周期性复盘（哪些可选字段实际没人填、哪个视图没人看、哪里卡住）→ 迭代。**复盘结论回写本文档**，形态变更必须有据可查。
- **复盘工具已就位**（2026-10-22）：`_体检.md` 带两节客观数据——**字段填充画像**（每主题每字段填充百分比，time 因内核自动打戳不列入）和**录入频率**（跨度/有记录天数/最长断档/当前断档/最近 14 天逐日）。印象会骗人，曲线不会。
- **第一次复盘结论（2026-10-22）**：`tags` 全库 0% 填充 → 字段移除（见 §5.1 表）。这是「从数据出发调记录结构」的第一次实战：0.4.0 时代凭「契约对称」补的字段，数据说没人用，就删。

## 6. 视图产出（记录必须有回报）

自由录入 ≠ 丢分析价值。每个主题的 `.base` 带八个视图（`core/vault.js#buildBase`）：

1. **全部事实**（总表，`what` 走摘要公式预览列）
2. **按谁聚合** / 3. **按在哪看板** / 4. **按方式看板** / 5. **按为何看板**（kanban 按各维度分组）
6. **时间线**（按 `when` 倒序）
7. **正值记录**（`howmuch > 0`）/ 8. **负值记录**（`howmuch < 0`）——资金主题即进账/出账两本账；非资金主题通常有一张空着，空着就对了

配套规则：

- **三张表预设 howmuch Sum**（2026-10-22 用户拍板，推翻早前「不预设 Sum」立场）：全部事实（默认视图）/ 正值记录 / 负值记录三张表带 `summaries: howmuch: Sum`——资金主题打开即见净流量与进/出总额，是「记录要有回报」最直接的一格。早前立场（跨行相加可能无意义）的残留顾虑由「Sum 是默认值不是强制」化解：非资金主题不理那格即可，用户在 Bases 里可删。录入路径不覆盖已有 base（`ensureTopic`），只有显式「重建」统一重写。**默认视图那处是 2026-10-22 真机验收后补的**：用户打开 `.base` 停在默认视图，只挂正/负表上的汇总根本看不见——汇总放在没人看的视图里等于没有；且混符号相加恰是资金主题的净流量，不是无意义数。
- **事实笔记题注行**（2026-10-22）：`事实/*.md` 正文顶部加一行元信息引用块（`> 2026-10-22 15:48 · 我自己 · 家里 · 测量 · 📊 71.8`）——打开一条事实不必在正文和属性面板之间来回跳。读模型的一部分（真源里没有），`parseFactFile` 负责剥掉它，体检读回的 `content` 永远是纯正文。
- **时间线**：Bases 没有原生 timeline 视图类型，内核抽一张 callout 笔记（`时间线.md`，全版本原生渲染）+ 一份深色 HTML（`时间线.html`）。不用 mermaid timeline 图表——老版本 Obsidian 会渲染成原始代码。
- **时间线从真源渲染**（2026-10-15）：数据源是 `_真源/facts.ndjson` 而不是 `事实/*.md`——真源是权威、字段更全，且手改读模型不污染时间线；更重要的是录入路径因此不再需要全库预读事实正文（见 §7 快照收窄）。
- **录入即刷新**：`commit()` 录后必刷时间线（`core/record.js`），静态读模型不刷就永远停在建主题时的空态。
- **`ensureTopic` 只在缺失时写视图**：用户被明确要求「要改视图就在 Obsidian 里改 `<主题>.base`」，录入不许抹掉那些改动；只有「重建」才覆盖（`resetViews`）。
- **重建清旧名 `.base` 孤儿**（2026-10-15 真机事故补）：主题目录被改名/搬家后，`<旧名>.base` 不会跟着改（宿主改目录名不改文件名），inFolder 写死旧目录名→ Bases 面板两个入口、一个打开是空的。`resetViews` 重生成时删掉「名字不是当前主题」的 `.base`（自建第二视图非文档化用法，误伤时重建确认框是知情同意点）。
- **视图文件名＝目录名，且体检负责监督**（2026-10-15 补，用户实机发现）：上面那条只覆盖了「目录改名」，用户直接把 `.base` 文件改名的场景仍是静默——体检报「全库干净」，而实际上插件的视图入口失效、下次记录还会补出第二份。定论（用户选严格立场）：**一个主题目录下只有一份 `.base`，文件名必须等于目录名**，异名的那份视为待清理的孤儿（重建删），不由人手维护。三处补齐静默：① 体检新增 `W_BASE_NAME` / `W_BASE_MISSING`（`core/vault.js#viewIssues`，告警而非致命——视图里查的是目录不含文件名，改名不会让视图变空，那是目录改名的症状）；② 插件 rename 事件命中 `<主题>/<异名>.base` 即弹窗，给「改回原名」（内容没坏，不必动真源重建）；③ 文档明写这条规矩。级别为何是告警：真源没事、不必改数据就能修，符合 `致命=必须改数据` 的判定。
- **时间线按月分段**（2026-10-15，用户拍板的形态变更）：`<主题>/时间线.md` 从"全量时间线"改成**索引页**（每月清单 + 最近 20 条，尺寸恒定），按月另出 `时间线-YYYY-MM.md` / `.html`。动机来自 `npm run bench` 的实测数据——单份 md 随事实线性上涨（1000 条 43KB、10000 条 412KB、30000 条 1.2MB），核心计算从来不是瓶颈（3 万条也才零点几秒），**卡的是宿主打开一个 1MB 的 callout 列表**，而且"每录一条重写全份"让单次录入成本也线性退化（2000 条时 9ms→37ms）。分段后录入/删除只重写受影响的那一个月份 + 索引页（`writeTimelineSegment`），成本与总量无关；全量 `writeTimeline` 只在 init/ensureTopic/resetViews/rebuild 走，并顺带清掉已经没有事实的月份文件（孤儿）。**这条「每次录入只重写当月」的承诺由 tests/timeline-segments.test.js 的「录一条只重写 4 个文件」守住**——一旦退回"重写全份"，测试立刻红。顺手修了时间线的排序 bug：标题写着"按日期倒序"，实际按真源出现顺序分组。
- **`_体检.md` 库根共享、新主题自动纳入**：CLI 不自动写（agent 场景显式调用），插件防抖自动写。
- **删除/更正**（2026-10-15）：`remove(topic, id)` 是唯一的破坏性写入——真源压缩重写 + 删 md + 刷时间线。存在的理由：「记错收拾不了」比录入摩擦更致命，用户会因此不敢记。壳一律先 dryRun 预览、人确认后才执行；恢复靠库自己的 git。**物理删除（无 tombstone、无删除标记）**是 2026-10-15 用户拍板的结论：个人记录场景不需要软删除——录错时用户要的就是「当没发生过」，而软删除（真源留 `deleted: true`）会让每个读模型都得处理「已删除」状态，复杂度全库蔓延；真要审计另开形态（tombstone / 追加删除事件行）。

## 7. 录入面

- **CLI**（agent 通道）：六个写入命令 `init / record / remove / audit / rebuild / import` + 一个只读命令 `主题`（给 agent 录入前对齐主题名，零写入所以不算写入面）。其中 `删除`（2026-10-15）是唯一的破坏性写入：默认 dryRun 预览，`--yes` 才执行，不可逆恢复靠 git。**写入面加命令 = skill 必须同版更新**（SKILL.md 是 agent 的契约）。
- **插件**（人的通道）：两阶段表单——阶段一选/建主题（候选来自现有主题目录，可输新名字就地建），阶段二纯 5W2H（who/when/what 必填 + time/where/why/how/howmuch 输选框，候选只取该主题历史、按使用频次排序；必填三项 label 带「（必填）」标记）。who 缺省＝「唯一才缺省」（2026-10-22 用户拍板，见 §4）。**输选框「有值也想重选」**（2026-10-23 真机反馈）：宿主 `<datalist>` 按框里的值过滤，选过一个之后点开只剩那一个，用户反馈"得先退格删掉才看得见全部选项"——先删再选是荒谬的交互。补丁 = **鼠标点进已有值的框时把值临时挪到 placeholder**（灰字显示原值，信息不丢），于是下拉是空值过滤、给出全量候选；没被真改过就失焦则悄悄搬回；只动显示不动数据（提交取 draft）。绑 `mousedown` 不绑 `focus`：Tab 进来是"我要改字"，点进来才是"我要挑一个"。**不用宿主自绘浮层 `AbstractInputSuggest`**（核过 asar：它在 showSuggestions 之后 500ms 自动关闭，"停下来看看有哪些选项"恰是它做不到的）；这条论据与守卫同在 `tests/plugin.test.js`。「记下来并继续」：录完不关窗，清叙事/数值留场景字段，连记场景（记账一天多笔）不用重走两阶段。命令面：记一条事实 / 跑体检 / 从真源重建 / 打开某个主题的事实视图（主题选择列表）/ 删除这条事实（对当前打开的事实笔记，先预览后确认）/ 复制这条事实（以旧稿为底稿录新的，表单预填直接进阶段二）/ 编辑这条事实（改内容：另存为新事实 + 删旧稿）。
- **编辑这条事实**（2026-10-15）：用户要的是「改这条」，形态上不给原地改——真源只追加，改旧行就是篡改历史。实现 = 复制 + 删除：**先录副本、成功后才删旧稿**，顺序是硬的：任何一步失败，最坏态都是「库里两条都在」（看得见、删一条就好）；反过来先删后录，一次失败就是这条事实彻底没了。复制/编辑共用同一个底稿来源（`duplicateDraftFromTruth(topic, id)`），差别只在提交后的收尾——删除的实现因此只有一份（`plugin.removeFact`，删除命令的确认回调与编辑的收尾共用）。**底稿取自真源、不取自 md**（2026-10-15 真机教训后改）：md 是读模型，手改过就可能缺字段，而最需要编辑的偏偏是记错的那条——拿 md 当底稿会把纠正路径堵死，也和"手改 md 不算数"自相矛盾；真源那条写入时就过过校验，永远完整。真源里找不到这条（孤儿 md）返回 null，壳提示先跑重建。UI 上把机制写在脸上（表单顶部明说「另存为新事实 + 删旧稿、id 会变、取消零副作用」），不再二次弹确认：表单本身就是核对界面。
- **复制这条事实**（2026-10-15）：以当前打开的事实笔记为底稿生成录入草稿——`when` 照旧（副本默认是"同一件事的修正版"，周期场景用户自己改日期）、`time` 重置为当前时刻、**`id` 绝不继承**（撞 `E_DUPLICATE_ID` 的就是它）。写入仍走 `record()` 正门（新 id 自动生成、四层一致）。 Obsidian 自带复制**不可替代**：字节级复制文件、真源不知情——体检报致命、时间线看不见、重建清掉、删除命令都不认。解析与草稿生成在 core（`core/record.js` 的 `duplicateDraftFromTruth`，壳经 session 这道门用；`duplicateDraft` 是纯函数，单测锁"输出永不带 id/time/recorded"）。与「删除」合成完整更正闭环：先建副本、核对无误再删旧稿。
- **会话级候选累积**（插件壳）：刚写入的文件要等 metadataCache 索引才进候选，壳在会话内累积已录值补上——纯展示层缓存，不是规则。
- **快照收窄**（2026-10-15）：时间线从真源渲染后，录入路径不再预读 `事实/*.md` 全文（`snapshotStore(bodies:false)`），从 O(全库) 读数降为 O(该主题真源)；体检/重建仍全量读（`bodies:true`，要逐条读回契约）。库变大录入变慢会劝退「坚持记」，这个引线提前拆。
- **主题重命名防御**（插件）：监听 rename，识别主题目录被改名/搬家（新路径下直接带 `_真源/facts.ndjson` 而旧路径没有了）→ 提示 `.base` 里写死的旧目录名会失效，确认后重建修复。静默的视图变空是这个项目要消灭的东西。
- **skill**：`skill/SKILL.md`，配 CLI 使用；版本号与插件同步（单一源头 `package.json`）。

### 8.1 跟版维护策略（F 的执行细则，2026-10-23 立）

**为什么这项目要专门管跟版**：写入路径（契约 / 真源 / 校验）是我们自己的，宿主改版它纹丝不动；但**"看"的那一半整个是租的**——八视图是宿主的 Bases、属性类型是宿主的 `types.json`、时间线靠宿主的 callout 与 BEE 表达式、控件行为与 API 语义也是宿主的。更麻烦的是**坏的姿势不一样**：写入路径坏了会大声报错（契约校验、错误提示都在），读模型坏了常常一声不吭（视图空着、汇总显示"无值"），用户只会觉得"数据没了"。

#### 版本敏感点清单（跟的就是这张表）

| 依赖的宿主部分 | 宿主改了会怎样 | 怎么查 | 怎么绕（现状） |
|---|---|---|---|

#### 已核实的宿主事实（Obsidian 1.14.4，2026-10-23 逐行读 asar 核过）

- **Bases 汇总**：数值型内建名 = `Average/Min/Max/Sum/Range/Median/Stddev`，其中 `Sum:"values.sum().round(2)"`；**视图级** `summaries: {属性: 公式名}`（我们用的）合法，**文件级** `summaries: {名称: 公式串}` 是自定义公式——两个东西，别混。
- **`AbstractInputSuggest`**：focus 即弹（`focus` → `onInputChange` → `showSuggestions`），但 500ms 自动关闭；`selectSuggestion` **不替我们 setValue**（宿主自带的文件建议子类才 `setValue` + trigger input/change）——走 `onSelect` 回调必须自己 setValue + trigger，否则输入框与 draft 静默分叉。
- **查证方法**：asar 是明文拼接的 JS（不压缩），可直接搜字符串；**大上下文 grep 会 SIGTERM/管道断开**，用 python + mmap 定位切片打印（`mm.find(b'EB=function')` 之类）。
