# solofact 设计规格与实验记录（SPEC）

本文回答「**为什么是这样**」和「**什么还没定**」。用法看 [README](../README.md)，演示库看 [vault-5w2h/README.md](../vault-5w2h/README.md)，发布流程看 [RELEASE.md](../RELEASE.md)——那三份是「是什么、怎么用、怎么发」，本文是「当初为什么这么定、哪些还是实验变量」。

> **重建说明**：本文档于 2026-10-15 由历史设计讨论重建，全部条目经代码与契约实证核对（核对来源随文标注：`contract/`、`core/*.js`、`cli/`、`plugin/`、测试运行结果）。章节编号沿用原 spec（§5.2 = 形态 A/B 实验设计、§8 = 开放项），保持历史引用有效。

## 1. 问题与立论

solofact 源自一个 CRM 实验（solocrm）的死因复盘：**工具不差，但没人坚持记**。

由此立下本项目的基本假设：

> 录入摩擦是「坚持记」的第一杀手。把摩擦压到最低（必填只三个字段），同时让每次记录**当场产出可看的视图**（记录有回报），坚持记的发生率会提高。

solofact 是这个假设的验证实验。因此本项目的验收标准从来不是「功能齐全」，而是「**有没有人在持续地记**」。当前状态：工程侧已可分发，但**真实使用数据一天都还没开始积累**（见 §8-B）——实验尚未真正开跑。

## 2. 架构护栏（不可动）

这些不是偏好，是防止「规则分叉」的结构性约束，改动需先改本文再改码：

- **一内核两壳**：`core/` 是纯函数核（不碰文件系统、不取当前时间），CLI 与 Obsidian 插件都只是调用者。
- **规则只有一份**：契约 `contract/enums-5w2h.json` + 校验 `core/fact.js#validate`，两个壳不许自带校验。
- **落盘顺序锁死**：真源（`<主题>/_真源/facts.ndjson`）先于 Markdown；致命错误一个字节都不写（`core/record.js#record`）。分叉的后果是「Markdown 存在但真源没有这一行」——正是本项目要消灭的静默错误。
- **插件只写不看**：不渲染表格、不做仪表盘；查看全部交给宿主 Obsidian 的 Bases。
- **测试锁架构**：`tests/` 35 条（内核 + CLI 子进程退出码契约 + 插件静态守卫「壳不许越界」）。

## 3. 数据形态：主题 = 目录

**主题不是事实里的一个字段，而是一堆事实的上级目录。**（2026-10-12 定论）

```
<库>/
├── <主题>/                   ← 一个主题 = 一个自包含目录
│   ├── _真源/facts.ndjson    append-only 真源（每条一行 JSON）
│   ├── 事实/f-*.md           读模型：一条事实一个文件
│   ├── <主题>.base           Bases 视图（八个看板）
│   └── 时间线.md / .html     该主题的可视化时间线
├── _体检.md                  ← 库根：跨主题汇总诊断（全库共享一份）
└── .obsidian/types.json      ← 库根：属性类型注册表（全库共享一份）
```

论据：

1. **没有 `type` 这一级**。主题从字段升格为目录后，同主题内 `howmuch` 天然同一量纲（记账都是元、体重都是 kg），类型模板和单位/口径校验失去存在理由——`validateAmount` 因此只校验「是不是数字」（`core/fact.js`）。
2. **删一个主题 = 删一个目录**，干脆；没有主题注册表要维护。
3. **无跨主题总览**（2026-10-12 决定：主题完全独立）。跨主题的汇总只有库根 `_体检.md` 一份诊断。
4. 真源是 append-only 的 ndjson，Markdown / `.base` / 时间线都是**可随时重建的读模型**——数据不会因为改视图而损坏。

## 4. 记录结构：5W2H

一条事实 = 5W2H 九个字段（`contract/enums-5w2h.json` v2）：

| 字段 | 必填 | 类型（`core/vault.js#TYPES_5W2H`） | 说明 |
|---|---|---|---|
| `who` 谁 | ✅ | text | 自由文本；插件侧是**输选框**（历史候选可复用，也可手填新建） |
| `when` 何时 | ✅ | date | 发生日；日期必须原样往返，脏日期不静默成功（`parseDate`） |
| `time` 时刻 | — | text | HH:mm；分钟精度的权威落点是 id |
| `what` 啥 | ✅ | text | 正文（`makeFact` 把 `what` 规范为 `content`） |
| `where` 在哪 | — | text | |
| `why` 为何 | — | text | |
| `how` 方式 | — | text | |
| `howmuch` 多少 | — | number | **有符号数**，见下 |
| `recorded` 记录日 | — | date | 录入日，与 `when` 的前后关系有校验 |
| `tags` | — | tags | |

设计论据：

- **必填只有 who / when / what**——直接对应 §1 的立论：录入摩擦压到最低，其余可选可空，不补不报错。
- **枚举从数据抽、按主题作用域**：契约里 `enums: {}` 是空的（设计，不是漏配）。候选在运行时从**该主题**已记过的事实抽取（插件 `historyOf`），词汇内聚不跨主题混。这是「自由录入」与「聚合复用」的统一机制。
- **`howmuch` 是有符号数**（2026-10-13 定调）：核心只校验「是不是数字」，正负零全放行。符号是**主题级约定**（资金主题 负=出、正=进），核心不可能知道每个主题的语义——全局判正负就是被删掉的 type 校验的还魂。
- **日期不加引号落盘**：宿主属性面板会把加引号的日期判成文本，Bases 就无法排序/分组/算区间（`dumpValue`）。

## 5. 形态演进与 A/B 实验记录

### 5.1 已废弃的形态（及废弃理由）

| 形态 | 内容 | 废弃理由 |
|---|---|---|
| v01 三层实体 | 客户/联系人/事实三层 + `shape` 开关 | 2026-10-12：记录结构是实验变量，可大幅重做；三层实体是默认假设不是需求 |
| type 级 | 度量算法模板 + 单位校验 + `fact-types.json` + `typeTemplate.js` | 主题=目录后，同主题 howmuch 天然同义，整套失去存在理由，已全部清除 |

### 5.2 A/B 实验方法论（原 spec §5.2）

- **记录结构/形态是实验变量，不是要固化的产品。** cli / skill / Obsidian 插件都是验证产品形态的手段，不是目的。
- 当前进行的实验：**5W2H 最低必填（who/when/what）与记录自由度的平衡点**——必填再少，事实不成形；再多，坚持率下降。分界在哪里，由真实使用数据回答，不由设计者拍脑袋。
- **「插件降低录入摩擦」没有人手秒数对照组**（2026-10-12 澄清）：CLI 是 agent 录入通道（配 `skill/SKILL.md`），不是人手界面。插件面对的是 Obsidian 里的人，实验对象是人的坚持行为。
- 实验方法：真库自用/试用 → 周期性复盘（哪些可选字段实际没人填、哪个视图没人看、哪里卡住）→ 迭代。**复盘结论回写本文档**，形态变更必须有据可查。

## 6. 视图产出（记录必须有回报）

自由录入 ≠ 丢分析价值。每个主题的 `.base` 带八个视图（`core/vault.js#buildBase`）：

1. **全部事实**（总表，`what` 走摘要公式预览列）
2. **按谁聚合** / 3. **按在哪看板** / 4. **按方式看板** / 5. **按为何看板**（kanban 按各维度分组）
6. **时间线**（按 `when` 倒序）
7. **正值记录**（`howmuch > 0`）/ 8. **负值记录**（`howmuch < 0`）——资金主题即进账/出账两本账；非资金主题通常有一张空着，空着就对了

配套规则：

- **不预设 Sum**：跨行相加仍可能无意义，用户要算自己在 Bases 里加 `summaries`（同主题内 howmuch 同义，求和才有意义）。
- **时间线**：Bases 没有原生 timeline 视图类型，内核抽一张 callout 笔记（`时间线.md`，全版本原生渲染）+ 一份深色 HTML（`时间线.html`）。不用 mermaid timeline 图表——老版本 Obsidian 会渲染成原始代码。
- **时间线从真源渲染**（2026-10-15）：数据源是 `_真源/facts.ndjson` 而不是 `事实/*.md`——真源是权威、字段更全，且手改读模型不污染时间线；更重要的是录入路径因此不再需要全库预读事实正文（见 §7 快照收窄）。
- **录入即刷新**：`commit()` 录后必刷时间线（`core/record.js`），静态读模型不刷就永远停在建主题时的空态。
- **`ensureTopic` 只在缺失时写视图**：用户被明确要求「要改视图就在 Obsidian 里改 `<主题>.base`」，录入不许抹掉那些改动；只有「重建」才覆盖（`resetViews`）。
- **重建清旧名 `.base` 孤儿**（2026-10-15 真机事故补）：主题目录被改名/搬家后，`<旧名>.base` 不会跟着改（宿主改目录名不改文件名），inFolder 写死旧目录名→ Bases 面板两个入口、一个打开是空的。`resetViews` 重生成时删掉「名字不是当前主题」的 `.base`（自建第二视图非文档化用法，误伤时重建确认框是知情同意点）。
- **`_体检.md` 库根共享、新主题自动纳入**：CLI 不自动写（agent 场景显式调用），插件防抖自动写。
- **删除/更正**（2026-10-15）：`remove(topic, id)` 是唯一的破坏性写入——真源压缩重写 + 删 md + 刷时间线。存在的理由：「记错收拾不了」比录入摩擦更致命，用户会因此不敢记。壳一律先 dryRun 预览、人确认后才执行；恢复靠库自己的 git。

## 7. 录入面

- **CLI**（agent 通道）：六个写入命令 `init / record / remove / audit / rebuild / import` + 一个只读命令 `主题`（给 agent 录入前对齐主题名，零写入所以不算写入面）。其中 `删除`（2026-10-15）是唯一的破坏性写入：默认 dryRun 预览，`--yes` 才执行，不可逆恢复靠 git。**写入面加命令 = skill 必须同版更新**（SKILL.md 是 agent 的契约）。
- **插件**（人的通道）：两阶段表单——阶段一选/建主题（候选来自现有主题目录，可输新名字就地建），阶段二纯 5W2H（who/when/what 必填 + time/where/why/how/howmuch/tags 输选框，候选只取该主题历史、按使用频次排序）。「记下来并继续」：录完不关窗，清叙事/数值留场景字段，连记场景（记账一天多笔）不用重走两阶段。命令面：记一条事实 / 跑体检 / 从真源重建 / 打开某个主题的事实视图（主题选择列表）/ 删除这条事实（对当前打开的事实笔记，先预览后确认）/ 复制这条事实（以旧稿为底稿录新的，表单预填直接进阶段二）。
- **复制这条事实**（2026-10-15）：以当前打开的事实笔记为底稿生成录入草稿——`when` 照旧（副本默认是"同一件事的修正版"，周期场景用户自己改日期）、`time` 重置为当前时刻、**`id` 绝不继承**（撞 `E_DUPLICATE_ID` 的就是它）。写入仍走 `record()` 正门（新 id 自动生成、四层一致）。 Obsidian 自带复制**不可替代**：字节级复制文件、真源不知情——体检报致命、时间线看不见、重建清掉、删除命令都不认。解析与草稿生成在 core（`core/record.js` 的 `duplicateDraftFromMarkdown`，壳经 session 这道门用；`duplicateDraft` 是纯函数，单测锁"输出永不带 id/time/recorded"）。与「删除」合成完整更正闭环：先建副本、核对无误再删旧稿。
- **会话级候选累积**（插件壳）：刚写入的文件要等 metadataCache 索引才进候选，壳在会话内累积已录值补上——纯展示层缓存，不是规则。
- **快照收窄**（2026-10-15）：时间线从真源渲染后，录入路径不再预读 `事实/*.md` 全文（`snapshotStore(bodies:false)`），从 O(全库) 读数降为 O(该主题真源)；体检/重建仍全量读（`bodies:true`，要逐条读回契约）。库变大录入变慢会劝退「坚持记」，这个引线提前拆。
- **主题重命名防御**（插件）：监听 rename，识别主题目录被改名/搬家（新路径下直接带 `_真源/facts.ndjson` 而旧路径没有了）→ 提示 `.base` 里写死的旧目录名会失效，确认后重建修复。静默的视图变空是这个项目要消灭的东西。
- **skill**：`skill/SKILL.md`，配 CLI 使用；版本号与插件同步（单一源头 `package.json`）。
