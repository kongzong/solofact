# solofact · 5W2H demo vault（主题 = 目录）

新一代记录形态的演示库：**5W2H 自由事实，按主题分库**。它不绑定任何场景——既能记业务接触、公司/家庭记账，也能记旅行、体重，任何"发生过的事"。

## 核心：主题是一个目录，不是一个字段

每个主题是库根下一个**自包含目录**，一堆事实的上级：

```
潮汕6日游/
  _真源/facts.ndjson     该主题 append-only 真源
  事实/f-*.md            该主题的事实（一条一个文件）
  潮汕6日游.base         该主题的 Bases 视图
  时间线.md / .html      该主题的可视化时间线
一人公司CRM业务/ …
公司记账/ …
家庭记账/ …
体重检测/ …
```

- **没有 `主题` frontmatter 字段**——主题就是目录名，从路径推断，不冗余存进每条事实。
- **没有 `type` 这一级**——同主题内 `howmuch` 天然同一量纲（记账类都是元、体重是 kg、旅行是元），所以不需要类型模板、不需要单位/口径校验。
- 删一个主题 = 删一个目录，干脆。根级只有共享的 `.obsidian/types.json`（属性类型）和 `_体检.md`（跨主题汇总的诊断报告）。

## 一条事实 = 5W2H

| 维度 | 字段 | 必填 | 输入方式 |
|---|---|---|---|
| **Who** 谁 | `who` | ✅ | 输选框：本主题历史里选，也能手填 |
| **When** 何时 | `when` (+`time`) | ✅ | 日期（时刻也是输选框） |
| **What** 啥 | `what` | ✅ | 自由文本（正文） |
| Where 在哪 | `where` | — | 输选框 |
| Why 为何 | `why` | — | 输选框 |
| How 方式 | `how` | — | 输选框 |
| How much 多少 | `howmuch` | — | 数字（**可负**：资金主题约定 负=出、正=进）；单位由正文/`how` 文本承载，同主题内天然一致 |

必填只有 **who / when / what**。其余想到了再补，不补不报错——这就是"记录要自由"的落点。

**枚举从数据抽、按主题作用域。** 描述字段（who/where/why/how/time/howmuch）的候选来自**当前主题**已记过的事实——每个主题的词汇内聚，选「一人公司CRM业务」时 who 只出现客户名，不会和「体重检测」的"我自己"混。第一次打开库是空的、随手填；记几条后下拉自然出现你自己的值。契约里 `enums: {}` 是空的——设计，不是漏配。

## 演示主题

demo 有 5 个主题，展示同一套结构通吃不同场景：

- **一人公司CRM业务**：客户接触，叙事为主，金额是项目额（元）
- **公司记账** / **家庭记账**：现金流（元）——同主题内 howmuch 都是钱，Bases 里直接 Sum 就是总额
- **潮汕6日游**：旅行开销（元）
- **体重检测**：体重（kg）——同主题内都是 kg，Bases 里 Average 就是平均体重

## 视图

### 每个主题一个 `<主题>.base`（Obsidian 核心功能，无需插件）

打开任一主题目录里的 `<主题>.base`，看八个视图（只索引本主题的 `事实/`）：

1. **全部事实** — 总表，除 `what` 外全部短字段
2. **按谁聚合** — kanban，每个 who 一列
3. **按在哪看板** — kanban，按 where 分列
4. **按方式看板** — kanban，按 how 分列
5. **按为何看板** — kanban，按 why 分列
6. **时间线** — 按 when 倒序的表
7. **正值记录** — 过滤 `howmuch > 0`（资金主题即进账/收款；体重、里程这类天然为正的主题全落这里）
8. **负值记录** — 过滤 `howmuch < 0`（资金主题即出账/支出；非资金主题通常为空）

四个表格视图都带一列 **摘要**（Bases 公式取 `what` 前 40 字 + 省略号）。`what` 是长叙述，表格只放摘要预览；完整叙事去 `时间线.md` 或点开笔记。表=索引，笔记=阅读。

> 想要汇总（比如「公司记账」净流量）？在 Bases 里给那张表加一行 `summaries: howmuch: Sum` 即可——正值表 Sum 是总收入、负值表 Sum 是总支出，同主题内 howmuch 同义，求和才有意义。内核不预设，交给你按需加。

### 每个主题一份 `时间线.md` / `时间线.html`

Obsidian Bases 没有原生 timeline 视图类型，所以内核从该主题的事实抽了一张可视化时间线，放在主题目录里，随「重建」刷新：

- **`时间线.md`** — Obsidian 原生 callout + 列表的竖向时间线（每天一个 `[!note]`，下面列当天事实），所有版本原生渲染。
- **`时间线.html`** — 同数据的深色卡片式 HTML，给浏览器/预览面板用。

它们和 `<主题>.base` 一样是读模型：真源才是事实，重建会覆盖。

## 架构

- 每个主题的真源：`<主题>/_真源/facts.ndjson`（append-only，每行一条 JSON）
- Markdown / `.base` / 时间线都是读模型，随时可删、由真源重建
- 重新生成 demo：`node build.js`
- 跨主题体检：`node ../../cli/solofact.js 体检 --vault .`（写根级 `_体检.md`）

## 记错了怎么办：删除（唯一的产品化纠正路径）

**在 Obsidian 里直接删 `事实/*.md` 文件是没用的**——真源（`_真源/facts.ndjson`）里那行还在，下次「从真源重建」会把文件**复活**。要删，走这两条路之一：

- **插件**：打开那条事实笔记 → 命令面板（Ctrl/Cmd+P）搜「删除这条事实」→ 确认弹窗里核对 who/when/what → 确认删除；
- **CLI**（agent 通道）：`solofact 删除 --vault <库> --topic <主题> <id>` 先预览，内容核对无误后加 `--yes` 重跑才真删。

删除 = 真源压缩 + 删 md + 刷时间线，**不可逆**（恢复只能靠这个库自己的 git——所以真库值得进 git）。之所以给它一条路，是因为「记错了收拾不了」比录入摩擦更致命：没人敢在一个错了改不动的库里记账。

### 不想删，想以旧稿为底稿改一条好的：复制

打开那条事实笔记 → 命令面板搜「**复制这条事实**」→ 表单直接打开在第二阶段，旧稿的字段全部预填（`when` 照旧，要改自己改；`time` 重置为当前时刻）→ 改完点「记下来」。新事实走正常写入（新 id、真源追加一行），旧稿原地不动——**先建副本、核对无误再删旧稿**，比任何"先删后建"的顺序都安全。

⚠️ **别用 Obsidian 自带的复制**（Ctrl/Cmd+D、文件管理器里复制粘贴）：那是字节级复制文件，真源完全不知情——造出来的副本会让体检报 `E_DUPLICATE_ID`（id 原样重复）、时间线看不见它、一次「重建」就把它清掉、连「删除这条事实」都不认这个文件。复制的唯一入口是插件的「复制这条事实」命令，因为它走的是和手动录入同一条正门。

⚠️ **也别直接改 `事实/*.md` 的内容**——它是**读模型**，事实的真源是 `_真源/facts.ndjson`（一行一个事实）。在 Obsidian 里手改 md 的后果是三层分裂：`.base` 视图扫的是文件夹，会立刻显示你改的内容；时间线读的是真源，看不见你的修改；真源本身纹丝不动。更隐蔽的是：体检读的也是 md——你改坏了它会报 `E_` 错误，你改好了它也不报，但**都不代表它承认**；下次「从真源重建」会把你的修改静默抹掉。想改内容的正道：复制这条事实（预填旧稿）→ 改 → 记下来 → 删旧稿；或改真源里那一行再「重建」。

## 更新插件

你的库会从 demo 慢慢变成真库——**永远不要整体覆盖更新**，那会动到你的数据。插件更新只换两个文件：

1. 拿到新版（单独的插件更新包 zip，或从新版 vault zip 里取 `.obsidian/plugins/solofact/`）
2. 把 `solofact/`（main.js + manifest.json）整个覆盖进 `<你的库>/.obsidian/plugins/solofact/`
3. 重启 Obsidian（或 设置 → 社区插件 里把 solofact 关掉再打开）

你的主题目录、事实、`_体检.md` 一个字节不碰。验证：插件面板里版本号已变。

## 看效果

用 Obsidian 打开本文件夹，点开任一 `<主题>/<主题>.base`。

> 插件 `plugin/main.ts` 的录入分两阶段：**阶段一**选/建主题（候选来自现有主题目录，也可输新名字就地建），**阶段二**录纯 5W2H——who/when/what 必填，time/where/why/how/howmuch 输选框（候选只取该主题历史，按用过的频次排序，输入框内无占位提示、字段描述在行内）。一天要记多笔（记账/CRM 场景）用「**记下来并继续**」：录完不关窗，清掉正文和数值、场景字段留着，接着记。本 vault 预装了 `main.js` 并启用，可直接在 Obsidian 里「记一笔」。
